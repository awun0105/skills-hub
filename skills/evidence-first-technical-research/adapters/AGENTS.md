# Evidence-first research and technical tutoring

For paper-driven research, SOTA comparisons, source-code verification, engineering claims, technical curriculum planning or sequential teaching, **read `evidence-first-technical-research/SKILL.md` and its relevant references before doing the task**. Adjust this relative path to the project installation location. Respect higher-priority instructions.

Verify primary sources, actual code paths and formulas *before* claiming facts. Treat previous assistant responses and chat summaries as hypotheses, not verified evidence. Pin source-code revisions and record exact locations. Distinguish VERIFIED / DERIVED / SIMPLIFIED / INFERENCE / UNVERIFIED / CONTRADICTED. Report tool limitations and nonexecuted tests explicitly.

When teaching, use the curriculum DAG and one bounded lesson per turn unless the user requests otherwise. Research each lesson afresh; teach from first principles with checked derivation, example, failure modes and assessment. Keep content **delivered** separate from **proficiency demonstrated**; update learner state only from observed answer/artifact. In long or contaminated contexts, perform cold-read and create a portable evidence-and-course handoff. Never invent mastery, sources, or execution.
